# 📚 Before You Read

**Find your next book. Know what to expect. Read without unwanted spoilers.**

A small, local RAG-based book discovery and reading companion built with React, Vite, FastAPI, LangChain, ChromaDB and Google Gemini.

## What it does

- Semantic book recommendations from a local 30-book knowledge base
- **Before You Read** spoiler-controlled reading guides
- Book comparison
- Preference-based recommendations
- Session chat history
- Three real spoiler modes: No Spoilers, Light Spoilers and Full Discussion
- Gemini 503/429 retry and fallback handling
- Gemini API key stays in the Python backend

## Requirements

- Python 3.11+ recommended
- Node.js 18+ recommended
- A Gemini API key

Google's current Python SDK is `google-genai`. The project uses it for Gemini generation and embeddings. The embedding model defaults to `gemini-embedding-001` because it is a stable text embedding model.

## 1. Backend setup — Windows

Open a terminal in the project root:

```powershell
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

Copy `.env.example` to `.env`:

```powershell
copy .env.example .env
```

Open `backend/.env` and add your real Gemini API key:

```env
GEMINI_API_KEY=your_real_key_here
GEMINI_MODEL=gemini-2.5-flash
GEMINI_FALLBACK_MODEL=gemini-2.5-flash-lite
GEMINI_EMBEDDING_MODEL=gemini-embedding-001
```

Do **not** put this key in the React project.

## 2. Build the ChromaDB knowledge base

Still inside `backend`:

```powershell
python ingest.py
```

This reads `backend/data/books.json`, creates LangChain documents, splits them into chunks, generates Gemini embeddings and creates `backend/chroma_db/`.

If you edit `books.json`, run `python ingest.py` again. The script recreates the local vector database.

## 3. Start the FastAPI backend

Inside `backend`:

## 5. How the RAG pipeline works

```text
User question
     ↓
FastAPI endpoint
     ↓
Gemini embedding for the query
     ↓
ChromaDB similarity search
     ↓
Relevant book chunks
     ↓
Retrieved context + spoiler mode + session history
     ↓
Gemini generation
     ↓
Answer shown in React
```

The application does **not** simply send the user's question directly to Gemini. Retrieval happens first, and the retrieved book records are inserted into the LLM prompt.

## 6. How recommendations work

The user describes a desired reading experience. The backend turns that into a retrieval query and searches ChromaDB. Gemini then chooses approximately three books from the retrieved collection and explains why each one matches.

The preference panel works the same way: selected genres, length, difficulty and reading preferences are converted into a semantic search query before generation.

## 7. How Before You Read works

The selected title and the user's request are embedded/retrieved against the book collection. The resulting book context is sent to Gemini with a dedicated Before You Read instruction.

In **No Spoilers** mode, the prompt explicitly forbids endings, culprits, major twists and major character reveals.

## 8. How spoiler control works

The frontend sends one of:

```text
NO_SPOILERS
LIGHT_SPOILERS
FULL_DISCUSSION
```

The backend inserts that value into the system instructions used for the Gemini call. Therefore the selector changes the actual model instructions instead of being decorative UI.

## 9. How ChromaDB is used

ChromaDB stores the vector embeddings of the local book knowledge base. A semantic query is converted into an embedding and compared with the stored vectors. The most relevant chunks are returned as context for Gemini.

## 11. How to change the Gemini model

Edit `backend/.env`:

```env
GEMINI_MODEL=your_available_model
GEMINI_FALLBACK_MODEL=another_available_model
```

The application reads these values at startup. You can therefore change models without editing Python source code.

If your selected model temporarily returns HTTP 503, the backend retries with exponential backoff and, if configured, tries the fallback model. The real exception is logged in the FastAPI terminal while the frontend receives a user-friendly message.

## 12. Common errors

### `503 ... model is currently experiencing high demand`

This is a temporary Gemini service/model availability problem. The app automatically retries and can use `GEMINI_FALLBACK_MODEL`. You can also change `GEMINI_MODEL` in `.env`.

### `429`

The API is rate-limited. The app retries a limited number of times. If it continues, wait before sending another request.

### `401` / `403`

Check that `GEMINI_API_KEY` is correct and available to the selected model/API.

### `The book knowledge base is unavailable`

Run:

```powershell
cd backend
python ingest.py
```

and restart the backend.

### Frontend says it cannot connect

Make sure this is running in another terminal:

```powershell
cd backend
uvicorn main:app --reload
```

## Security

`.env` is ignored by Git. The Gemini key is only read by Python. The React application never receives the key.

## Scope

This project intentionally avoids authentication, databases for users, Docker, Redis, PostgreSQL, microservices and cloud deployment. It is designed as a small educational RAG project that is easy to understand and extend.
